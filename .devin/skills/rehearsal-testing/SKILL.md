# Rehearsal testing skill

This document is the contract between the pipeline implementation and the test/eval
suite. **It must be updated in the same commit as any change to pipeline stages or
eval cases.** `npm run check:skill-sync` fails the build otherwise.

## Pipeline stages (src/lib/orchestrator.ts, PIPELINE_STAGES)

- `discover` — default `REHEARSAL_BROWSER=auto` crawls with the plain fetcher (`probeFetcher`): a page that `looksLikeJsShell` (explicit js-required markup / empty app-root with scripts / near-zero actions+text with scripts) retries once via `FirecrawlClient.scrape`, and pages failing with no HTML get the same rescue before being marked failed; a seed page with < `MIN_SEED_LINKS` (3) links expands once via `/v1/map` bounded by `config.firecrawlMapLimit` (default 20). `REHEARSAL_BROWSER=<pref>` opts the crawl into a browser runner (browserbase-function / stagehand / stagehand-local / playwright); Stagehand pools one browser session per viewport per crawl (`releaseCaptures` frees it when the stage ends; sessions are keyed per run `scope` so concurrent runs share nothing)
- `simulate` — persona swarm (`src/lib/simulation/{persona,swarm}.ts`): ≤`maxAgents` agents walk the real site; per step a single batched `jev.decide` scores every candidate action + a `__leave__` option, a seeded RNG samples the pick; journeys are emergent and end `goal-reached` or `dropped-off` (first-class `dropOff` reason). Runner capability gate: `runPersonaJourney` absent → legacy seeded sampler (`≥500` trajectories; one `choice` call per distinct scoring payload; a per-run signature cache dedupes identical inputs such as viewport twins of a URL)
- `verify` — swarm mode replays `selectJourneys` (most-dropped + most-travelled interleaved, ≥1 goal-reached) action-by-action; legacy mode runs risk-ranked trajectories in real desktop/mobile browsers. Successful navigation plus all compiled assertions OR any discovered goal endpoint satisfies verification and compare; endpoint alternatives are separate evidence, not failed checks. `tests/unit/endpoint-goal-success.test.ts` covers the cost → pricing endpoint regression, findings/emits, compare, empty goals and navigation/probe errors. Simulation retains any-positive goal matching through the shared predicate. `REHEARSAL_VERIFY_AGENT` swaps scripted locators for an observe/act/extract agent loop (`browser/agent.ts`, runners with `supportsAgent`)
- `analyze` — rule-based + Gemini findings, each classified by evidence type + usability principle; LLM evidence deduped to one state per URL
- `compare` — DOM-patch variant applied in isolated context; baseline vs variant deltas
- `spec` — SpecReport generated (one change per finding, each with an ordered `steps` edit list); spec.md written under data/experiments/<id>/; per-run model usage (`experiment.usage`, `llm` + `jev` call/token totals) is stamped on every save and each call logged as a `llm-call`/`jev-call` telemetry event; the spec-applied site mockup is generated in the same stage (Gemini `mockup` model slot → deterministic template fallback), stored as experiment.mockup, served at /experiments/:id/preview/[/slug]
- `rebuild` — brand extraction from crawled states → goal inference from CTAs/nav/titles/endpoints → per-goal branded page generation (Gemini, deterministic template fallback); opt-in: a full run stops at spec and rebuild runs only via `POST /api/experiments/:id/rebuild`; stored as experiment.rebuild, served at /experiments/:id/rebuild[/slug]

## Run lifecycle (not a pipeline stage)

- `POST /api/experiments` returns the `Experiment` as soon as the record exists (`status: "queued"`); the pipeline runs as a background job via `scheduleRun` (`ctx.waitUntil` on Workers through `src/lib/jobs.ts`, detached promise elsewhere) that waits for a `withRunSlot` slot and the per-experiment lock, and marks the experiment `failed` on unhandled errors.
- **Chunked runs (Workers durability).** `scheduleRun` stamps a fresh `runToken` + `runCheckpoint` ({stage, attempt}); the background job runs bounded slices (`REHEARSAL_STEP_BUDGET_MS`, default 20s) and each suspension re-invokes itself via `POST /api/internal/run-step` (per-run `runToken` body auth, or `Authorization: Bearer $REHEARSAL_RUN_SECRET`) so every slice gets a fresh waitUntil window; off-Workers slices loop in-process. Hops target `REHEARSAL_ORIGIN` when set, else the run's stored `runOrigin` — never the current request `Host` — and skip the SSRF guard only on loopback. A stage that survives >`MAX_STAGE_SLICES` (10) slices fails with `STAGE_TIMEOUT` instead of spinning.
  - `discover` checkpoints every `DISCOVER_CHECKPOINT_PAGES` (5) crawled pages or `DISCOVER_CHECKPOINT_MS` (10s), whichever comes first, checked after each page; a step-budget suspension always saves. The checkpoint includes frontier/attempted/visited/states/edges + signature-probe progress and resumes via `GraphBuilder.restore`. A killed slice redoes only work since the last checkpoint, rather than resuming from every completed page.
  - `spec` saves the spec before attempting the mockup and clears the run checkpoint on completion. Resume/run-step discard non-rebuild checkpoints only when a spec exists and the pipeline finished (`complete`, `rebuilding`, or a pending rebuild); an interrupted spec stage still completes its mockup and final status update. `rebuild` continues from its persisted site plan and page batches (see below). Other stages restart on resume.
- Background runs acquire the experiment lock before a pipeline slot; the watchdog skips locally locked experiments. Slots and experiment locks use expiring leases (`REHEARSAL_RUN_SLOT_TTL_MS`, default 330000ms) to recover abandoned requests; an old lock's cleanup cannot release its replacement. Stage POSTs wait up to 20s for capacity before busy 429 + Retry-After. The rebuild client retries only busy 429s, up to four retries / 120s of delays.
- A stalled opt-in rebuild (status `rebuilding` or a pending site) gets a `rebuild` checkpoint, including interrupted planning without a site. Standalone rebuild steps persist that checkpoint before planning and clear it on completion. Without a site the dashboard offers Build site instead of polling indefinitely. Ordinary pipeline runs still stop at spec.
- **Stall watchdog.** `Orchestrator.resume(id)` (via `POST /api/experiments/:id/resume`, the experiment GET poll, or any caller) re-kicks a run whose last activity is older than `REHEARSAL_STALL_MS` (default 180s), picking up at the stored checkpoint. `rescan` refuses with 409 while a checkpoint-bearing run is still heartbeating; a stale checkpoint doesn't block.
- Idempotency + site dedupe: the `Idempotency-Key` header / `idempotencyKey` body field and `normalizeSiteUrl(targetUrl)` dedupe to the existing record (`dedupe` field in the response) before consuming the daily-create budget.
- `POST /api/experiments/:id/rescan` re-probes the URLs in `experiment.siteSignatures` with the plain fetcher and compares `contentSignatureFor` — changed pages → artifacts reset + background re-run (202); unchanged → no-op (200); a new `goal` regenerates on the kept graph.
- `PROVIDER_QUOTA` (`402`/`429` patterns): with a browser-runner crawl, discover falls back from the runner to the plain fetcher; a quota-dominated zero-state crawl throws `PROVIDER_QUOTA` instead of `DISCOVERY_EMPTY`. Firecrawl `402`/`429` responses classify the same way.

Whole-site rebuild: `rebuild(id, {restart?})` persists one planning step or a batch of six pages; pipeline resume loops steps with a fresh LLM budget until the deadline (one planner call, two calls per page including retry; other stages retain their configured budgets). `rebuildPending` signals continuation. `tests/unit/rebuild-site.test.ts` covers sitemap normalization, planner/footer fallback, page sanitization/retry, links, lint, shared CSS/document shell and durable batches. `tests/unit/rebuild-serving.test.ts` covers optional catch-all home/nested/CSS/not-rebuilt responses, strict CSP, traversal rejection and real orchestrator API step progression with a fake LLM; public run allowance is charged only for planning/restart. The rebuild dashboard loops POST steps and displays sitemap progress, retaining old goal pages. `rebuild-stage.eval.ts` checks planning followed by continuation to completion; legacy `generateRebuild` tests remain for old goal pages.

## Eval cases (tests/evals/, gated by evals.config.json thresholds)

- `core.eval.ts` — extraction coverage, simulation determinism/scale, Jev mapping validity, rubric coverage, stale-date finding (Scenario B), spec completeness, variant idempotency, SSRF guards
- `invariants.eval.ts` — behavioral invariants on fixture HTML + fixture adapters:
  - profile shaping — on a journey graph (AIE home → schedule hub → day pages, every other action a detour leaf), `impatient` mean actions-to-goal ≤ `exploratory`, pooled over seeds 1337/2026/7 (`maxImpatientToExploratoryStepRatio`, `minGoalReachedPerProfile`, `profileTrajectoriesPerSeed`). The file mocks `randomUUID` with a counter because FixtureJevClient's tiebreak jitter is keyed by actionId — without it outcomes drift run to run
  - verification ranking — `rankForVerification` keeps every trajectory incl. goal-reached; `selectTrajectories` keeps ≥1 goal-reached for every N on an adversarial pool and a simulated pool, and never fabricates one (`minGoalRetentionRate`)
  - spec ordering — `generateSpec` orders changes by severity desc (stable within a tier), critical/high changes land in phase 1, markdown emits `## Rebuild plan` with one `### <phase>` per phase (`minRebuildPhases`)
  - graph dedup — `GraphBuilder` collapses identical-stateHash states (same page, reordered/recased actions) into one node; viewport change makes a new node (`maxStatesPerStateHash`)
  - vague labels — finding on `fixtures/vague-labels.html` names exactly the vague labels found; no finding on the AIE fixture (`minVagueLabelsDetected`)
  - stale date — finding description cites every detected past date; no finding before the event ends (`minPastDatesDetected`, `requireStaleDateEvidence`)
- `intents.eval.ts` — RFX intents (information / quotation / proposal) + endpoint discovery; thresholds are local constants in the file:
  - AIE fixture — `detectSiteType` = event; `discoverEndpoints` finds ≥1 `schedule-event` ("Explore all 50 sessions", "Schedule") and ≥1 `signup` whose label says apply; top endpoint weight ≥ 0.75; weights deterministic and in [0,1]; `defaultIntentsForSite` yields one goal per category; "find the conference schedule" → information targeting `schedule-event`; no endpoint findings when CTAs sit on the start page
  - synthetic journeys — orphaned /signup → `endpoint-unreachable` (navigation); pricing 4 clicks deep → `endpoint-deep` (mindless-choices, median 4, sample path recorded); absent expected class → `missing-endpoint-class`; `endpointJourneys` deterministic per seed
  - orchestrator wiring — fixture runner/store/adapters: `discover` stores `intents` + `endpoints`, endpoint class assertions (`endpointGoalAssertions`) make reaching /talks satisfy `goalSatisfiedInState`, `analyze` stores `journeys`, and the experiment round-trips through the `Experiment` contract (what GET /api/experiments/[id] serializes)
- `questions.eval.ts` — unanswered visitor questions (`visitorQuestions` = bank + start-page context questions → answer detection) on the AIE fixture, thresholds in evals.config.json (`minQuestionBankSize`, `minAieQuestions`, `requiredAnsweredQuestions`, `requiredUnansweredQuestions`, `maxAieUnansweredRatio`):
  - answered with cited start-state evidence — homepage what/do/start, `when-where` (Nov 10-12 + //LOCATION/venue), `attend` (apply CTA), `agenda`, `speakers`, `recordings`
  - unanswered — `cost` (application-only, no price anywhere), `ctx-apply-criteria` (copy says "by application only" but never says who gets in or when), `contact` (the only contact-form CTA is sponsorship, which answers `sponsor` instead)
  - `questionFindings` emits one `unanswered-question` finding per gap + an "N of M" summary, start screenshot as evidence; deterministic across runs with the fixture LLM
  - orchestrator wiring — fixture adapters: `analyze` stores `questions` on the experiment, adds the `unanswered-question` findings, and the experiment round-trips through the `Experiment` contract

- `metrics.eval.ts` — page metrics (`src/lib/browser/metrics.ts` `measurePage`) on the AIE fixture in hermetic local Chromium (loopback server, all other requests aborted, `networkidle` so layout settles): repeat measurements are identical; homepage fold ratio ≥ `metricsMinHomepageFoldRatio` with scroll time = screens × 1.5s; exactly `metricsExpectedH1Count` h1 and it is the largest text; ≥ `metricsMinNavItems` primary-nav items, ≥ `metricsMinCtas` CTAs, `primaryCtaAmbiguity` ≤ `metricsMaxPrimaryCtaAmbiguity`, ≥ `metricsMinFontSizeBuckets` font sizes; the HTML-only fallback matches the DOM facts and nulls layout fields; `metricFindings` emits every rule in `metricsRequiredRules`, no CTA-ambiguity finding, each citing a usability principle + screenshot evidence
- `sandbox.eval.ts` — `CodeSandbox` (`src/lib/sandbox`): node worker executes agent-style assertions on the AIE fixture with console + `report()` output, deterministic repeat runs, non-throwing failure path; `selectSandbox` honours `REHEARSAL_SANDBOX` and falls back to `node-vm-worker` when no `Sandbox` binding exists; `agentVerifyEnabled` is opt-in and `selectRunner` backends declare `supportsAgent`
- `findings-dedup.eval.ts` — cross-state finding dedup (`src/lib/analysis/dedupe.ts` `collapseFindings`, called by `analyze`): on four AIE fixture states + two browser runs failing the same assertion, raw `ruleFindings` repeats per state, collapsed output has one finding per (principle + title) whose affected states/actions/evidence paths are the union of the group, severity = max, first findingId kept, title suffixed `(N of M pages)` (pages counted by URL, so desktop + mobile states of one URL are one page) / `(N of M runs)`; verified failures with different assertions stay distinct; orchestrator `spec` on a multi-page fixture site (clock pinned after the event) emits each finding and spec change once
- `bench.eval.ts` — benchmark harness (see "Bench harness" below): manifest contract validation, an end-to-end fixture-site run, two-run determinism (identical reports with timing stripped), and scoring unit tests (ruleKey normalization, expected/tolerated/unexpected precedence, precision/recall edges)
- `swarm.eval.ts` — persona swarm (`src/lib/simulation/swarm.ts`) end-to-end through the orchestrator on the AIE fixture site (`FixtureSiteRunner.runPersonaJourney` walks the in-memory page map): journeys deterministic per seed, every agent gets a persona from the site-derived mix, drop-offs carry first-class `dropOff` reasons whose distribution sums to the dropped count, journeys land in `simulations` as `Trajectory`s (heat/dashboard compat), `verify` replays the most-travelled + most-dropped emergent journeys (`run_agent-N_<viewport>` run ids). Thresholds are local constants (`maxAgents`, `minDropOffs`, `minGoalReached`, ...)
- `rebuild.eval.ts` — rebuild-quality eval scaffold: validates the SpecReport + spec markdown the harness emits (changes by impact, rebuild phases), with `describe.todo`/`it.todo` placeholders naming the future rebuild-fidelity evals

## Bench harness (`npm run bench`, tests/evals/bench/)

`scripts/bench.ts` runs every `tests/evals/fixtures/*.manifest.json` site through the full pipeline hermetically and writes `data/bench/{report.json,report.md}` (gitignored — never commit reports). Contracts live in `src/lib/contracts/bench.ts` (`FixtureSiteManifest`, `BenchSiteReport`, `BenchReport`); the harness itself is `tests/evals/bench/{sites,runner,pipeline,score,report}.ts`.

- **Fixture sites**: a manifest declares `pages` (URL path → fixture HTML file under tests/evals/fixtures/), `mountPath`, `goal`, and what the pipeline should produce — `expectedEndpointClasses`, `expectedFindings` (must be produced), `toleratedFindings` (count toward precision, not recall), `unexpectedFindings` (false positives), `expectedSpecItems`, `budgetsMs`, `expectations` (metric floors). `stubMissing: true` serves a deterministic stub for unmapped subpaths.
- **Runners**: `FixtureSiteRunner` resolves pages from the manifest map in memory (trajectory verify walks action hrefs, assertions evaluate on the final page's extracted content); `HermeticSiteRunner` (`--browser`) uses local Chromium with every non-origin request aborted — same hermeticity as spec-delta.
- **Determinism**: seed 1337 default, counter `randomUUID` patched via `syncBuiltinESMExports` (also mocked per-file in evals — Jev tiebreak jitter is actionId-keyed), optional `referenceNow` pins the clock for stale-date heuristics; stage durations use `hrtime` so pinning doesn't zero them. Strip `durationsMs`/`overBudget`/`generatedAt` to compare two runs (`stripTiming`).
- **Scoring** (`score.ts`): findings group into rule keys (digit-normalized title + principle); precision = (expected+tolerated matches)/produced, recall = expected-matched/expected; journey/state coverage from trajectories; endpoint coverage from `journeys`; spec item coverage = matched `expectedSpecItems`/`expected` total (1 when none declared). `expectationFailures` lists every violated floor — `--check` exits non-zero when any site has one.
- **Flags**: `--site <id>` one site, `--out <dir>` report dir, `--browser` chromium runner, `--seed`, `--check` gate mode.
- `mockup.eval.ts` — spec-stage mockup (`src/lib/mockup`) + spec change enumeration, thresholds local to the file:
  - spec enumeration — `generateSpec` covers every findingId, every change carries ≥1 `steps` line (recommendation first, then named controls/pages); an LLM spec that drops a finding gets the deterministic change appended and empty steps backfilled; markdown emits a `Steps:` list per change
  - mockup pages — `generateMockup` on the AIE fixture yields one self-contained page per crawled URL (root → `index`); no `<script>`/`<img>`/`<link>`/`url()`/`@import`; internal links rewritten to `/experiments/:id/preview/:slug`; byte-identical across runs with the fixture LLM
  - LLM hardening — hostile Gemini HTML is sanitized (scripts/img/event attrs stripped, `mockup:<slug>` and crawled URLs resolved to preview paths, uncrawled same-origin links neutralized, foreign http(s) exits kept); pages the LLM skipped fall back to the template
  - orchestrator wiring — `spec` stores `experiment.mockup` alongside `experiment.spec`; both round-trip through the `Experiment` contract
- `rebuild-stage.eval.ts` — rebuild stage (`src/lib/rebuild`) with fixture adapters; thresholds are local constants in the file:
  - brand extraction — `brandSignalsFromHtml` on the AIE fixture returns the site name, ≥ 8 nav items (Apply to attend, Speakers, Program…) resolved against the page URL, and a cssVars record; `rollupBrand` over the fixture states is deterministic (two calls deep-equal)
  - goal inference — `inferGoals` on a fixture-built experiment returns ≥ 4 goals: the experiment goal first (source `experiment-goal`), ≥ 1 `cta`-sourced goal, unique url-safe slugs, weights in [0,1]
  - generated pages — `generateRebuild` with `FixtureLlmClient` yields one page per goal; no `<script>`, every `<img src>` on the audited origin, each page contains its goal's CTA label; byte-identical across two runs
  - orchestrator wiring — fixture runner/store/Jev/LLM: `rebuild` (chaining every earlier stage) stores `experiment.rebuild`, it round-trips through the `Experiment` contract, discover stores per-state `brand` signals, and `rebuild.llm` is the fixture adapter name; `runAll` stops at spec (complete, no `experiment.rebuild`)

## Unit tests (tests/unit/)

- `metrics.test.ts` — `measurePage` via `PlaywrightRunner.openPage` on synthetic pages served from loopback (scroll, CTA prominence ties, heading skips/multiple h1, nav count, font buckets, trunk test), `metricsFromHtml` fallback, and each `metricFindings` rule (grouping, severity, evidence)
- `core.test.ts` — contract parsing (incl. `ExperimentConfig` budget upper bounds, clamping of over-limit stored configs), extractor, graph dedup, mulberry32 determinism, profile shaping, fixture Jev scoring, patch compilation, rule findings, spec markdown
- `questions.test.ts` — question bank shape, homepage-first ordering, context-derived questions, answer detection (endpoint class / URL / text, start-only homepage questions, endpoint label filters, re-answering stored questions), LLM refinement skip + keyword questions, `unanswered-question` findings + summary
- `egress-guard.test.ts` — SSRF: `resolvePublicHost` rejects private/link-local/metadata/unspecified hosts; the loopback egress proxy (`src/lib/fetch/egress-proxy.ts`) refuses CONNECT + plain-HTTP to private IPs; a real Chromium behind it gets 403 on redirect hops to 169.254.169.254 / loopback and on internal subresources, and `assertPublicPage` rejects the blocked final URL
- `access.test.ts` — `REHEARSAL_ACCESS_TOKEN` gate (`hasAccess` Bearer/Basic, `src/proxy.ts` 401 on every route only when set) and the `withRunSlot` concurrency cap (`REHEARSAL_MAX_CONCURRENT_RUNS`, slot freed on error)
- `orchestrator-lock.test.ts` — per-experiment run lock: a second concurrent `discover`/`spec`/`runAll` on the same experiment throws `StageInProgressError` (route → 409) without calling the runner again; other experiments run in parallel; the lock is released after success and failure
- `agent-activity.test.ts` — `ActivityEvent` contract, `JsonFileStore.appendActivity`/`activity` (order, per-experiment isolation, `ACTIVITY_EVENT_LIMIT` cap, hostile-id safety), orchestrator emission during discover/verify/markFailed, and `GET /api/experiments/:id/activity` (feed + 404)
- `experiments-route.test.ts` — `POST /api/experiments` returns 400 for configs over the budget bounds, before the rate limit, URL check or store write; in-bounds configs are capped to the demo `MAX_TRAJECTORIES`/`MAX_VERIFY_RUNS`; `targetUrl` is the only required field (≤2048 chars; `goal` ≤500, else 400 `invalid request`) — `goal` may be omitted and is forwarded undefined; creates are deduped by `Idempotency-Key`/site before the rate limit and `scheduleRun` kicks the background pipeline on a fresh record
- `run-limits.test.ts` — public-demo run budget on a mocked D1: `ipBucket` (IPv4, IPv4-mapped, IPv6 → /64), `POST /api/experiments/:id/run` 429 past `RUN_PER_EXPERIMENT_PER_DAY` and past `RUN_PER_IP_PER_DAY` across one /64, 403 on a `complete` experiment unless the access token is presented (a first `rebuild` after `spec` stays allowed), 404 before spending budget; rescan shares the budget and 400s an over-long goal
- `experiments-async.test.ts` — async lifecycle + dedupe/rescan: `normalizeSiteUrl`/`contentSignatureFor` cases, `classifyError` `PROVIDER_QUOTA`, `startExperiment` idempotency-key + site dedupe, `rescan` changed/unchanged/goal-only paths, discover's runner→fetcher quota fallback, `enqueueRun` slot retry
- `firecrawl.test.ts` — `looksLikeJsShell` heuristic cases; `FirecrawlClient` no-key no-op, `/v1/scrape` POST shape + Bearer auth, `/v1/map` limit, `interact` bounded at `FIRECRAWL_MAX_INTERACT_ACTIONS`, `402`→`PROVIDER_QUOTA`, `success:false`, `assertPublicUrl`; orchestrator wiring: plain fetch first, JS shell → scrape retry, low-link seed → bounded map expansion, no-key = fetch-only
- `run-durability.test.ts` — chunked run lifecycle: slice suspension/resume mid-crawl (fake clock), checkpoint replay keeps graph + signatures, `MAX_STAGE_SLICES` → `STAGE_TIMEOUT`, `resume` staleness gate, run-step route auth (401/400/404/202), `rescan` 409 on a live checkpoint
- `verify-without-browser.test.ts` — `BROWSER_UNAVAILABLE` (workerd default) and `PROVIDER_QUOTA` runners: verify records a `verify` failure and skips replays, compare leaves the variant `proposed`, spec still completes with no run error
- `stage-rerun.test.ts` — re-running a stage replaces that stage's own results: a second `verify` yields the same baseline `browserTests` (no duplicate run ids, compare's variant run kept after them), a second `compare` leaves one variant / variant run / comparison / `compare` failure, and an `analyze` re-run counts each baseline run once (variant runs excluded)
- `jobs.test.ts` — run-step hop targeting: `REHEARSAL_ORIGIN` pin beats the request origin, stored `runOrigin` is used over Host, loopback self-hops skip the SSRF guard, no hop off-Workers
- `probe.test.ts` — first-page probe (`src/lib/intents/probe.ts` `inferGoalAndPersonas`, run by `createExperiment` when `goal` is omitted): goal + ≤3 personas derived from the page's own CTAs/nav/endpoints, empty-page fallback (`Learn what {host} offers` + one Info-seeker), determinism, orchestrator wiring (inferred `goalSource` + stored `personas`, no fetch with an explicit goal, probe-failure `default` fallback)
- `llm-output-validation.test.ts` — LLM output is checked against the contracts before it is stored: `compileAssertions` keeps only valid `Assertion`s (null selector = absent, keyword fallback when none survive), `llmFindings` drops non-`Finding` items, `generateSpec` ignores malformed summary/changes/phases, `JsonFileStore.save` rejects invalid experiments and `list()` skips unparseable documents
- `intents.test.ts` — `classifyGoal` keyword heuristics, LLM refinement fallback, endpoint label/path classification, `discoverEndpoints`/`weightEndpoints` determinism + overrides, optional Experiment fields
- `swarm.test.ts` — persona loop + swarm driver on a mock runner: seed determinism, `maxConcurrentAgents` bound, drop-off reasons + distribution, runner-failure resilience (drop-off `error`), `personaWeights` from endpoints/intents, `selectJourneys` interleave + goal-reached retention, `journeysToTrajectories`, `Experiment` round-trip with `swarm`

## Browser tests (tests/e2e/)

- `discovery.spec.ts` — hermetic: serves the AIE fixture over localhost, verifies real-browser extraction + the stale-CTA precondition. Requires `REHEARSAL_ALLOW_PRIVATE=1` (set inside the spec).

## Layer 1 facts (scripts/verify-facts.ts)

`npm run check:facts` checks deterministic facts so neither an LLM nor a reviewer has to (docs/verification.md): stored experiments (`data/experiments/**`, `tests/fixtures/experiments/**`, `docs/runs/**/summary.json`) parse with the `Experiment`/`SpecReport` contracts with no unknown keys; every env var read in src/ is in `.env.example` and README/docs (and vice versa), and the terraform stacks declare + map the deploy subset (`DEPLOYED_ENV`, exemptions listed in the script); usability principle slugs/K-ids in `src/lib/analysis` + `src/lib/intents` exist in docs/krug-principles.md and the contract enum; every stable finding rule id (`f_<rule>_…`, metric `finding("<rule>")`) is referenced by a test; every `src/app/api/**` route + method is in docs/api.md. `--json` prints machine-readable results. After changing the pipeline output shape, regenerate the stored fixture with `npx tsx scripts/verify-facts.ts --write-fixtures` (hermetic run on `aie-code-2026.html`, mocked ids + clock, byte-identical across runs).

## Spec delta (PR comment, informational)

- `npm run spec:delta` (`scripts/spec-delta.ts`) runs the full pipeline (`discover` → `spec`) on `tests/evals/fixtures/aie-code-2026.html` served from loopback (other same-origin paths get a deterministic stub page; every non-loopback request is aborted), with fixture Jev/LLM, seed 1337, maxStates 12, 200 trajectories, verifyCount 2, desktop only. `randomUUID` is replaced with a counter so ids — and the Jev tiebreak jitter keyed by them — are stable. Writes `data/spec-delta/{summary.json,delta.json,comment.md}`; `--screenshot` also starts `next start` (or `next dev` without a build) and captures `/experiments/<id>` to `dashboard.png`.
- The summary (counts, findings grouped by digit-normalized title + principle with max severity, endpoint classes with reached/discovered + top weight, spec headings) is diffed against `tests/golden/aie-code-2026.summary.json`. `.github/workflows/spec-delta.yml` posts/updates one sticky comment ("Rehearsal spec delta", marker `<!-- rehearsal-spec-delta -->`) and uploads the screenshot as the `rehearsal-spec-delta` artifact. Deltas never fail the job; a crash or an empty graph/spec does.
- Update the golden with `npm run spec:delta -- --update-golden` and commit it in the same PR whenever a delta is intended: changes to findings rules/severity/titles, endpoint classification or weights, simulation/verification selection, spec generation, crawl limits, or the fixture itself. Don't update it to silence an unexplained delta — investigate first. If CI and local disagree (fonts/layout), regenerate from the CI artifact's `summary.json`.

## How to run

- `npm run test` — unit tests
- `npm run eval` — eval suite (CI gate; threshold-driven)
- `npm run test:e2e` — Playwright hermetic browser tests (needs `npx playwright install chromium`)
- `npm run check:skill-sync` — this file vs. PIPELINE_STAGES + eval files
- `npm run check:facts` — Layer 1 drift checks (above)
- `npm run check` — everything
