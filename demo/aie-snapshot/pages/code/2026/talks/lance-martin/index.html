Exploring Claude's Frontier

Formalizing a mathematical proof is different from writing a convincing explanation.

Lance MartinAnthropicMember of Technical Staff

Day 2 livestream · 3:48:31–4:06:52 on YouTube. The player starts and stops at this session’s boundaries.

Introduction#

Lance Martin of Anthropic examines two long-horizon capabilities: agents building their own coordination structures, and agents reorganizing memory after an experience rather than only recording notes during it.

Formalizing a mathematical proof is different from writing a convincing explanation. Every step must fit a computational system that can check it. Martin begins with Fermat's Last Theorem and the effort to formalize its proof in Lean, using it as a demanding example of work that must remain coherent across many agents and many hours.

The theorem states that no positive integers satisfy (a^n+b^n=c^n) for an integer exponent (n>2). The task here is formalization of an existing mathematical result, not a claim that an agent newly discovered the theorem or replaced the original proof.

Martin reports an earlier effort with a relatively small agent team, domain-specific orchestration, and substantial researcher support. His next experiment asks whether a much larger team can construct its own coordination machinery from more general primitives.

Give the team shared state without prescribing its organization#

03:51:11

The experiment uses a thousand agents, with one designated lead and the others acting as helpers. Each has its own sandbox. Shared Git and a SQL database provide the principal coordination mechanisms.

“Simple primitives” does not mean an unsecured or unmonitored execution environment. Martin describes restricted network access, real-time monitoring of tool calls, and periodic offline review of agent activity. The simplification concerns the task-specific collaboration scaffolding, not the removal of safety infrastructure or the Lean proof checker.

At 3:51:50, the architecture separates agent collaboration infrastructure from sandboxing and monitoring.

Early in the run, the lead creates database tables for announcements, worker assignments, notes, subtasks, and landed work. These tables were not a detailed workflow supplied in the initial prompt. They were coordination artifacts the team constructed to make the work manageable.

Announcements communicate changes that affect the whole team. Assignments divide the proof into responsibilities. Notes let workers share progress, while landed-work records distinguish a promising attempt from something incorporated into the shared result.

Martin's visualization shows agents reading and writing those structures over the run. For difficult parts, they build further task dependencies. Workers reallocate as statements are completed. The observed capability is not simply parallel generation; it is maintaining a usable shared organization while the problem changes beneath it.

Martin reports that the run completed the formalization over roughly 30 hours. That is Anthropic's reported experiment, not an independently reproduced result in this reading edition. Its architectural lesson is narrower and useful: sufficiently capable agents can create project-management abstractions from Git and a database rather than requiring every collaboration rule to be designed in advance.

3:55:51 ↗

Memory written in the moment is not a coherent knowledge base#

03:55:51

The second half turns from coordinating workers to coordinating knowledge across sessions. An agent writes a note because something seems useful now. Future work needs a different property: a coherent, nonredundant map of what is known.

Those are not the same optimization problem. A detail that feels important during an investigation may be transient. An early interpretation may be wrong. Repeated notes can preserve the same observation in several incompatible forms.

Martin draws an analogy with the distinction between daily experience and later consolidation in human memory. The engineering proposal does not depend on treating agents as human brains. It is to separate two operations: recording useful information during work, and revisiting that information afterward to improve its organization and reliability.

A memory directory only helps if the agent uses it well#

The first experiment gives an agent a sequence of questions about a database. Each question starts a fresh session, but a notes directory persists between sessions. The instructions simply make that directory available rather than prescribing an elaborate memory procedure.

Martin shows that the benefit varies by model. Some models do not reliably decide when to write or read memory. Stronger models in the comparison more effectively preserve verified observations and retrieve them when later questions require them.

The Pokémon example makes the difference visible. An older model's directory grows into a large collection of experience records. A stronger model's directory is smaller and more strategic, preserving tactical knowledge that is not easily recovered from the immediate game state.

File count is not the goal. A large archive can be less useful than a short set of dependable insights. The interesting behavior is selection: recognizing what will remain valuable after the current context disappears.

4:01:16 ↗

Dreaming can change the representation, not just shorten it#

04:01:16

Martin calls the later consolidation step dreaming. Its input can include full transcripts and notes written during sessions. Its output need not be another summary of the same shape.

At 4:01:25, the diagram distinguishes a searchable event log, written notes, representations such as wikis, and context proactively loaded into future sessions.

A transcript provides a detailed event history but is expensive to search repeatedly. Notes select salient observations. A wiki can connect those observations into a navigable structure. A small amount of especially important information can be promoted into context that every future session receives.

Dreaming is the operation that revisits these layers and changes what belongs where. It can remove a misleading note, fill a missing connection, or construct a better representation from the underlying evidence.

Correct a bad memory before it keeps steering the agent#

Martin's game example contains a wrong location note. The agent repeatedly trusts it, mislocalizes itself, and falls into a trap that reverses progress. Persistence turns one mistake into a recurring behavior.

In the comparison he shows, memory without consolidation leaves the agent stuck. A dreaming step revisits the history, corrects the mistaken representation, and allows progress to resume. The important distinction is between forgetting and correcting. The system needs to stop propagating the false belief while retaining useful knowledge about the game.

He then moves to a company-document corpus, comparing raw search with a wiki built from the material. Additional consolidation compute improves the wiki's usefulness for answering questions in the reported evaluation. Combining the wiki with search performs better still. The representation is not a replacement for every retrieval path; it can complement access to the source material.

The final example is less dramatic but familiar to anyone who has generated documentation: a wiki contains placeholders for pages that do not exist. A later pass fills those gaps and creates an index. The first output looked like an organized knowledge base; subsequent work made it behave more like one.

Martin ends with that distinction between writing memory and maintaining it. Durable notes do not automatically become durable knowledge. The system needs time and mechanisms to correct errors, close gaps, and reorganize what future sessions will rely on.
